with the contract choices in [ADR-v0.3.md](ADR-v0.3.md) and
[V0.3_DESIGN.md](V0.3_DESIGN.md). Upgrade/rollback and CLI/MCP examples are in
[V0.3_RUNBOOK.md](V0.3_RUNBOOK.md). This report distinguishes real model turns,
real CLI/daemon tests without model turns, and deterministic adapter simulations.

native authentication failure. The real three-harness scenario therefore uses
**OpenCode → Codex → OMP**. No four-harness native-success claim is made. Two
Claude identities are exercised by deterministic relay/transport/adapter isolation
checks, not by two authenticated Claude model sessions.

The final three-harness test has a real publisher produce a contract marker,
publishes immutable version 1, explicitly grants recipients, then publishes a
*different* version 2. Codex consumes pinned version 1. Its result is persisted
as a context artifact and explicitly granted to OMP. OMP reviews both pinned
contract and implementation result. All three results are observed in the original
conversation lifecycle events. The ungranted wallet principal is denied context
and receives no runtime session. This is provider-backed routing/reference/lifecycle
validation driven by the relay API; it does **not** claim that the models themselves
invoked MCP publication/delegation or edited repository files.

The lifecycle test observes a genuine native text delta before cancellation;
verifies that the queued second turn has zero attempts while the first is busy;
checks adapter cleanup and explicit restart; completes the queued turn once;
then shuts down during a third streaming turn. Reopen preserves its ambiguous
`uncertain_execution` failure with one attempt. Starting the adapter does not
replay that task. These are owned OMP sessions, not an arbitrary interactive attach.

## Resource observation

The native log ends with machine-generated JSON from 100 ms process-tree RSS
sampling. The sampler includes the test relay and all native descendants, counts
shared pages once per process, and can miss peaks shorter than its sampling
interval. It does not include unrelated system workloads or Go compilation.
The measured kernel is `6.18.54.1-microsoft-standard-WSL2`; `/proc/meminfo`
reported `MemTotal: 6069952 kB` and cgroup `memory.max` was `max` (no additional
cgroup cap). The final run took **15.971 s** and peaked at **1,173,640 KiB (about 1.12 GiB)** aggregate RSS.
The representative scenario stayed below the requested 6 GB budget. This is not
a guarantee for large contexts or many simultaneous native agents.

## Failures retained and limits

During incremental development a CLI branch initially missed a return and an
ACL test expected four denials after making three denied calls. Both were fixed
before the passing milestone/full-suite runs. An early pair of simultaneous
native test runs collided on the same canonical Codex session lock; the lock
correctly rejected the second owner. Subsequent runs used sequential native
execution. No uncertain side-effecting turn was automatically retried. Claude's
missing login is not represented as integration success.

Release-blocking deterministic isolation/authorization regressions pass. Remaining
scope limits are explicit: no Claude provider assertion, no four-harness assertion,
no model-initiated MCP delegation proof across all adapters, no arbitrary interactive
attachment, no binary/large streaming artifacts, no role/wildcard context ACLs,
no graph edits/forward task references, no automatic context garbage collection,
no native tool-side-effect rollback claim, and no P1 write worktree/approval/merge
support. The adapters remain read-oriented; same-OS-user native tools are not an
OS isolation boundary. Existing session/repository locks and manual reconciliation
remain essential. Migration rollback uses a pre-upgrade backup; downgrading the
schema in place is unsupported.
