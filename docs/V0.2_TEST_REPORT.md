# Meshra v0.2 test report

## Baseline and implementation boundary

The v0.1 owner-validated implementation was extended in place. Initial `go test ./...` passed in 7.49 seconds wall time: nine tested packages, plus `internal/model` with no separate tests. Existing registry/WAL, bounded queue, exact routing, cancellation, event replay and conservative interrupted-execution recovery were reused rather than replaced.

`docs/V0.2_DESIGN.md` was written before material schema/protocol changes. Schema migration is 1 → 2; domain/API `schemaVersion` remains 1. Existing HTTP/CLI contracts and all seven v0.1 MCP names remain. Intentional compatibility changes are documented: successful text is buffered/redacted before persisted deltas, offline delivery can exhaust before its deadline, idempotency is operation-scoped, and terminal history expires under configured retention.

Tests ran on Linux x64/WSL2. Installed harness/tool versions, actual native protocol observations and official citations are in [V0.2_ADAPTER_VERIFICATION.md](V0.2_ADAPTER_VERIFICATION.md). No provider credentials were printed or added to project configuration.

## Actual CLI, HTTP and MCP smoke

The credential-free smoke launches the built daemon twice, registers five identities across all four harnesses, verifies two distinct Claude names, persists/deduplicates a queued request across restart, cancels it, checks trace correlation, waits for an offline deadline, retrieves metrics and doctor, rejects invalid authentication and unauthorized sends, and launches the **real** `meshra mcp stdio` executable with an agent-only credential to initialize and retrieve a correlated trace. It emitted `smoke:"passed"`, `providerTurns:0`, and passed all assertions. It never starts a provider runtime by default.

The opt-in native smoke exercises the same actual executable path and adds scoped OMP-origin API → Codex provider reply, a reverse Codex-origin CLI → OMP provider turn, and a queued Codex request across full daemon restart. It verifies exact native session reuse, one dispatch after recovery, immutable origin/correlation, and retrieval by the stopped original OMP session's credential. It is **API/CLI-driven routing**, not model-initiated native OMP/Codex MCP delegation and not injection into an arbitrary interactive terminal.

## Migration, retention and additional safety regressions

- `TestPopulatedV1MigrationAndFutureVersionRejection`: upgrades a populated v0.1 database, preserves task/message/correlation identity, task sequence and event cursor/data, preserves same-operation deduplication, permits the same key for a different operation, executes retained queued work, and refuses schema 99 without downgrading it.
- `TestFailedMigrationRollsBackWithoutLosingV1Data`: invalid legacy JSON aborts migration; original schema version and task row survive.
- `TestRetentionPreservesActiveAncestryAndDropsExpiredHistory`: removes expired task/events together while protecting active work and its historical parent.
- Workspace removal/replacement, unsafe registry identifiers/configuration, unsupported write enablement, realistic credential formats, redaction idempotence and preserved native session identifiers are covered.
- Event metadata carries stable request/correlation/session/attempt identity; end-to-end SSE replay validates ordered distinct progress across store pages, successful concatenated text and terminal completion. Legacy metadata cannot reconstruct historical attempt-specific sessions that were never stored.
- `TestMCPProxyAcceptsLargeBoundedTrace`: real relay/API/proxy path retains terminal trace and a valid large JSON-escaped result rather than failing at the old 1 MiB transport cap.
- `TestSplitStreamCredentialsNeverReachEvents`: API-key and current turn-token fragments split across native deltas do not survive persisted text reconstruction.
- `TestResumeRestoresPermissionsWithoutRepeatedAppend`: native-shaped OpenCode append semantics restore the safe policy once and avoid repeated append on later turns.

Backup/rollback instructions are in [V0.2_OPERATIONS.md](V0.2_OPERATIONS.md). Transaction rollback/recovery was tested; restoring an entire historical deployment/native-store backup was documented but not executed against a separately installed old binary. Logical redaction/deletion is not secure erasure from old pages, WAL or backups.

## Failures found and addressed during this task

1. The first integrated run encountered an obsolete end-to-end assertion that MCP must have exactly seven tools. The incidental count assertion was removed, not re-pinned; actual authenticated tool behavior remains tested.
2. Native OpenCode PATCH concatenation was observed against the installed server and confirmed in pinned official source. The adapter's previous every-turn PATCH caused unbounded permission-list growth. The exact-tail check and append-semantics regression fix this without broadening approvals.
3. Security review reproduced split text-credential persistence and large valid trace rejection. Before fixes, the targeted command below failed both tests; after fixes it passed, and both pass under the final race suite:

   ```sh
   go test ./internal/relay ./cmd/meshra -run 'TestSplitStreamCredentialsNeverReachEvents|TestMCPProxyAcceptsLargeBoundedTrace' -count=1
   ```

   Successful delta text is now bounded/aggregated/redacted, failed/cancelled partial buffers are discarded, and MCP stdio responses have a bounded 32 MiB limit. Text-timing compatibility implications are explicit rather than hidden.
4. The first large-trace race run exceeded that new test's five-second completion allowance while persisting hundreds of events under instrumentation. Its bounded test allowance was increased to 30 seconds; production timeout semantics were not weakened. The final race case passed.
5. One release smoke observed an offline request still queued beyond its two-second post-wait grace. An instrumented follow-up and twelve bounded reproduction rounds passed before the timer change; the isolated observation was not reproduced, so its exact cause is **not established**. Inspection identified that relative wake intervals could be extended by scheduling/persistence/log work. Timers now retain absolute due times until work finishes, and the slow-claim/non-cooperative-runtime regression plus final real smokes pass. This does not prove that mechanism caused the isolated observation. Durable timeout recording can lag during process/storage stalls; waiting reports HTTP 202/current state rather than fabricating completion.

## Verification limits and integration checklist

- **Claude/OpenCode paid provider and model-initiated MCP turns are not live-verified.** Installed CLI/SDK/native HTTP capabilities were inspected; Claude reports not logged in, OpenCode native provider credentials were absent. Go subprocess/HTTP tests are simulations. Authenticate natively, then run each documented `MESHRA_AUTH_SMOKE=1` test and the two-Claude native routing/MCP checklist in [adapters-sdk.md](adapters-sdk.md).
- Actual native credential-free OpenCode health/session/permission/abort/delete observations and OMP metadata resume were performed separately; idle abort is not active destructive-tool cancellation evidence.
- Native permission hooks and read-only settings are not universal filesystem containment. OpenCode trusted plugins/native configuration remain outside session tool-approval confinement. No approval bypass or write enablement was introduced.
- Unknown/unlabelled secret formats can remain sensitive. Native stores/backups are separate and unencrypted; no general secret detector or exactly-once claim exists.
- No hard real-time deadlines, arbitrary interactive-session attachment, remote exposure, automatic heartbeat service, or automatic Git worktree creation are claimed. Optional P1 heartbeat/worktree automation was not implemented; manual redrive/retry configuration and diagnostics are included.
- No native Windows/macOS execution, real detached-process cancellation, remote side-effect rollback, or full historical-binary rollback drill was performed.
