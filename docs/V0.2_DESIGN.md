# Meshra v0.2 design

## Baseline and scope

The existing Go/SQLite/HTTP/SSE/MCP implementation is extended in place. Baseline `go test ./...` passed on 2026-10-19 (nine tested packages; model has no tests; 7.49 seconds wall time). Existing functionality includes persistent registration, WAL/FULL SQLite, an exclusive daemon lock, bounded durable admission, exact named-instance routing, one turn per identity plus repository locking, cancellation/deadlines, manual retry, persisted paginated events, and conservative crash recovery. Existing adapter contract tests use protocol-faithful subprocesses/HTTP servers; opt-in provider tests are not baseline live evidence.

## Compatibility

Keep `schemaVersion: 1`, task IDs, all v0.1 endpoints/CLI commands and MCP names. New task fields are additive. Logical `claimed` maps to existing `dispatching`; logical delivery is an additional persisted `delivered` event before the existing `running` state. Transport acceptance remains the transactional `queued` event, not downstream completion. Existing agent values `registered`, `starting`, `idle`, `busy`, `stopped`, `error` remain; stopped/registered are offline, error is unhealthy. Registration never asserts a running runtime. Remote binding remains prohibited, stronger than an opt-in remote service and appropriate to the local-only scope.

## Durable dispatch, retry and ambiguity

The single owning daemon holds the OS lock throughout its lifetime. Persist claim owner, lease expiry, attempt, destination session, retry availability, error category and ambiguity flag with task state and lifecycle event in one transaction. The lease expires at the task deadline; it is an ownership/reconciliation record, not permission to overlap a still-running invocation. `dispatching`/`running` on restart always become failed/ambiguous, regardless of lease expiry. No automatic retry is allowed after adapter invocation. Unknown adapter errors are ambiguous. Late output cannot overwrite a terminal state, and the turn/repository slot stays occupied until Run returns.

Only failures *before* adapter invocation are automatically retryable. An offline destination receives persisted bounded exponential backoff with jitter and a maximum delivery-check policy; no native process is automatically started. Busy session/repository contention queues without consuming offline retries. Dispatch attempts retain their v0.1 meaning (Run admissions), separate from delivery checks. Default offline backoff starts at one second, caps at thirty seconds, and allows sixteen checks; deadlines take precedence. Explicit start wakes ready queued work without waiting for a previous offline backoff. Exhausted offline work fails with a nonambiguous category; manual redrive is administrator-only and explicitly warns of repeated effects for ambiguous work.

Keep scheduler wakeups as absolute deadline/retry timestamps until scheduling work has finished, then compute the timer's remaining duration. Slow persistence/logging must not restart an interval measured before that work. Durable terminal state can still lag while the process or storage is unavailable; waiting returns the latest nonterminal task rather than inventing completion.


## Idempotency, sessions and correlation

Use `(sender, sender_session, operation, idempotency_key)` uniqueness, preserving the stricter existing native-session isolation while adding operation scoping. Same-operation duplicate submissions must match destination, text and ancestry; conflicting reuse returns 409. Existing v0.1 records migrate without losing keys, IDs, sequence or events. Deduplication lasts as long as the retained task (default thirty days after terminal completion; active work is never pruned); no exactly-once execution claim. Parent deadlines cap child deadlines. Requests and results remain on the same task with immutable correlation/origin fields; callers can optionally wait for a terminal reply under a bounded request deadline without cancelling on transport disconnect.

## Access and sensitive data

Retain outbound operations/destination policies and administrator authority. Add optional recipient sender/operation allowlists; omitted lists preserve v0.1 behavior, explicit empty lists deny. Worktree writes remain denied by adapter capability: a policy requesting writes must be rejected unless an adapter can enforce approvals; relaying never grants tool approval. Enforce canonical directories again before runtime startup. Audit denials without payloads or credentials. Redact recognized credential forms in persisted payloads/results/events/errors and never emit content in structured lifecycle logs. Store a request fingerprint computed before redaction so deduplication still detects different secret-bearing inputs. Redaction is defense in depth, not a general secret detector; callers must not submit credentials.

Security review reproduced credential leakage when native text deltas split a key or per-turn token across events. v0.2 therefore buffers at most 256 KiB of native delta text per active turn, redacts the complete successful text, and only then persists bounded `delta` chunks before completion. Progress/session/approval events stay immediate. Cancelled/failed turns do not persist partial delta buffers. An overflow uses the bounded final successful result instead. This necessary compatibility change delays text availability until successful turn completion; native adapter streaming capabilities are unchanged. Consumers must concatenate delta data, not depend on native chunk count or timing. Existing SSE replay tests cover complete text/terminal delivery; a failing-before regression covers split credentials. MCP stdio responses receive a bounded 32 MiB budget to accommodate JSON-escaped Task/Trace duplication in text and structured content.


## Observability and retention

Persist correlation/session/sender/recipient/attempt metadata on events, and emit payload-free structured lifecycle logs with latency/error class. Add task trace, metrics and doctor using the existing CLI/API conventions. Doctor probes executable/version/workspace availability without displaying credential values. Metrics are lightweight database-derived counters/gauges, not a separate service. Configurable terminal-history retention applies to tasks and their events atomically; no active task, active invocation or ancestor referenced by retained work is deleted. An expired task returns 404; SSE cursors are global monotonically increasing sequence IDs and may have gaps from other tasks or retention. Reconnect within a retained task replays persisted pages.

## Migration and rollback

Apply numbered embedded migrations transactionally after v0.1 initialization; reject databases newer than this executable. Rebuild the tasks table to add operation-scoped uniqueness, preserving primary sequence IDs and foreign-key event relationships. Verify migration with a populated v0.1 database and future-version rejection. SQLite WAL and five-second busy timeout remain. Stop the daemon before backing up SQLite and native session directories; rollback means restoring the entire pre-upgrade backup, not downgrading an upgraded file in place.

## Non-goals and validation

No brokers, distributed orchestration, automatic session selection, unmanaged interactive-session attachment, approval bypass, workflow planner, dashboard or automatic worktree modifications. Optional P1 work is not required for the P0 cutover. Validate all twelve plan scenarios with existing and new behavior tests plus the actual CLI/daemon smoke, repeatable resource measurement, migration/recovery checks, and individual installed-version/official-source verification. Report provider tests as live only when actually executed; otherwise identify simulations and exact missing prerequisites.
