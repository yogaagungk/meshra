No Go tests, builds, linters, or formatters were run during this adapter work. No provider prompt was submitted. Earlier authenticated OMP/Codex results in [verification.md](verification.md) are historical evidence, not new v0.2 runs.

### OpenCode 1.19.3

The real owned local server reported its loopback ephemeral readiness URL. Observed results:

| Request | Observed result |
| --- | --- |
| unauthenticated `GET /global/health` | HTTP **401** |
| authenticated `GET /global/health` | HTTP **200**, `{"healthy":true,"version":"1.19.3"}` |
| authenticated `GET /doc` | HTTP **200**, OpenAPI **3.1.0** |
| `POST /session` with safe rules | HTTP **200**, nonempty session ID, expected directory, rules equal to submitted rules |
| `GET /session/<that exact ID>` | HTTP **200**, same native ID |
| `PATCH /session/<id>` with the same rules | HTTP **200**, returned rules **not equal** to the submitted list |
| idle `POST /session/<id>/abort` | HTTP **200**, `true` |
| `DELETE /session/<id>` | HTTP **200**, `true` |

The PATCH difference is explained by pinned official source: session update invokes `Permission.merge(current.permission, payload.permission)`, which concatenates lists. Evaluation selects the **last matching** rule. It is not replacement and is not a missing-policy failure. The source also confirms legacy `/permission/{requestID}/reply` and v2 `/api/session/{sessionID}/permission/{requestID}/reply`; inventing `/permission/v2/...` would be wrong.

### Substantive fix from this evidence

Previously the OpenCode adapter appended its full safe permission list on every turn, including fresh creation, causing unbounded duplicate persisted rules. It now reads the session's returned permission list and skips PATCH only when the exact safe list already forms its tail. A legacy/modified list without that suffix still receives the safe tail before prompting. No approval is broadened, no existing session is replaced, and no new wire method is used.

`TestResumeRestoresPermissionsWithoutRepeatedAppend` models the native concatenation semantics: an existing broad rule must receive one safe tail, and three resumed turns must issue exactly one PATCH. The fake server now retains and appends real-shaped permission lists. These Go changes and this new regression were **not run during implementation**; integration verification belongs to the parent.

## Enforcement matrix: `worktreeWrites: false`

This is a deny-writes policy, **not a universal OS sandbox guarantee**. Harness-owned transcript/cache/auth writes outside the worktree still occur. No adapter advertises interactive approval or write-capable approval enforcement; requesting write enablement must remain rejected at the relay policy boundary.

| Adapter | Exact native session/isolation controls | Write/approval controls already present | Strict boundary and unverified part |
| --- | --- | --- | --- |
| OMP | Hashed per-identity state directory + flock; explicit fresh session or saved-ID resume; verifies returned ID and session-file containment | Builtins removed; extension/skill/rule/LSP/PTY paths disabled; discovery-source overlay and project MCP disabled; `always-ask`, never auto-approve | Tool-free native configuration, **not an OS sandbox**. Overlay settings and native executable/environment remain trusted; this pass did not prove the runtime tool registry stays empty under every native customization. |
| Codex | Hashed per-identity `CODEX_HOME` + flock; auth file only shared, user config not imported; effective hooks/MCP/plugins rejected; returned thread and turn ownership checked | Native read-only sandbox and network-off policy; command/file requests declined, permission grants empty, unknown requests fail closed | Strongest native write boundary of the four, conditional on functioning native OS sandbox. This pass saw accepted policy, not an attempted write under it. No unrestricted fallback. |
| Claude | One owned SDK query/process per turn; saved SDK ID only, no latest/continue/fork; changed returned ID rejected; filesystem settings disabled; strict declared MCP | `PreToolUse` denies every tool except read/search and known Meshra tools; `canUseTool` also denies; default mode, bypass explicitly false | Tool-policy enforcement, **not an OS sandbox**. Separate identity sessions do not imply separate OS users, home directories, credential stores, filesystems, or security domains. Claude/OpenCode native storage is shared with the same OS user, unlike the OMP/Codex per-identity state roots. None provides a verified arbitrary-interactive-session attachment mechanism.

## Cancellation and delivery boundaries

OMP attempts `abort`; Codex attempts `turn/interrupt`; both close and reap the owned process group after error/cancellation. Claude uses a process-group SIGTERM, AbortController, Go wait-delay cleanup and final SIGKILL. OpenCode attempts bounded HTTP abort before owned server teardown. Code and simulated contracts support those mechanisms; only **idle** OMP/OpenCode abort requests were exercised natively here.

A cancellation response is not proof of rollback, completed upstream cancellation, or reversal of tool/MCP side effects. Process-group cleanup cannot promise to stop a deliberately detached external process or remote service. No exactly-once delivery, effect-free retry, or blind replay after `Run` is justified by these observations.

Run Go verification only after all changes land:

```sh

```

The existing opt-in commands below submit real provider turns and may incur charges. Run separately; preserve failed outcomes instead of replacing them with a simulation:

```sh

MESHRA_REAL_CODEX=1 go test -v ./internal/adapters/codex -run '^TestRealSmoke$' -count=1
MESHRA_AUTH_SMOKE=1 go test -v ./internal/adapters/claude -run '^TestAuthenticatedSmoke$' -count=1
MESHRA_AUTH_SMOKE=1 go test -v ./internal/adapters/opencode -run '^TestAuthenticatedSmoke$' -count=1
```

- OMP: valid native provider/profile/broker auth and permitted model; optional `MESHRA_OMP_MODEL` / `MESHRA_OMP_PROVIDER` overrides. Storage presence alone is insufficient.
- Codex: working native login (`codex login`) and model entitlement; optional `MESHRA_CODEX_MODEL` / `MESHRA_CODEX_PROVIDER`. The adapter does not inherit custom provider definitions from normal `config.toml`.
- Claude: authenticate using the discovered bundled CLI (`bridges/claude-agent-sdk/node_modules/@anthropic-ai/claude-agent-sdk-linux-x64/claude auth login`) or supported native SDK environment authentication before daemon launch. Optional `MESHRA_CLAUDE_MODEL`. Current prerequisite is missing authentication, not a missing executable/SDK.
- OpenCode: authenticate a supported provider with the local CLI (`bridges/claude-agent-sdk/opencode/node_modules/.bin/opencode auth login`); select both `MESHRA_OPENCODE_PROVIDER` and `MESHRA_OPENCODE_MODEL`, or neither for the native default. Current prerequisite is a verified authenticated provider/model. Relocated installation can use `MESHRA_OPENCODE_BIN`.

Each basic smoke exercises prompt and exact native-ID resume, not cross-harness MCP, every approval variant, attempted worktree mutation, or cancellation during a real tool. Those require separately observed integration scenarios. OMP/Codex deliberately expose no automatic task-bound MCP; Claude/OpenCode implement it but no authenticated MCP result is asserted by this report.

## Integrated release evidence

After the adapter reconnaissance above, the integrated release run passed the opt-in OMP/Codex provider prompt-and-exact-ID-resume tests. The real CLI/HTTP/MCP smoke also passed three routed OMP/Codex provider turns, correlated reply retrieval, and queued exact-session recovery after daemon restart. These are authenticated provider results, unlike the earlier credential-free probes. Routing is driven by scoped API/CLI credentials, **not** model-initiated OMP/Codex MCP delegation. All four adapter contract suites passed under the Go race detector. Claude/OpenCode provider turns remain unverified for the stated credential prerequisites; see [V0.2_TEST_REPORT.md](V0.2_TEST_REPORT.md) for exact commands, final results and limitations.

The v0.2 trace tool was added to the Claude/OpenCode agent-tool allowlists; administrator registration/retry/metrics/doctor tools remain outside automatic harness approval. Relay-level text buffering/redaction changes text persistence timing, not the native wire protocols described above.
