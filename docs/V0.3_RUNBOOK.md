# v0.3 runbook

Build `go build -o meshra ./cmd/meshra`; start `./meshra serve`. New options:
`--context-bytes 32768 --artifact-bytes 65536 --delegation-fanout 16`.
The first two can be lowered to 1024; fan-out range is 1..64. Existing flags,
private state directory, admin token and daemon lock behavior are unchanged.

## Upgrade, backup and rollback

1. Stop admitting new work. Inspect running tasks and their external effects;
   stop agents/daemon cleanly. Shutdown may leave a running turn ambiguous.
2. With **all** daemon processes stopped, copy the whole private data directory
   to an access-restricted backup. Preserve `meshra.db`, any `-wal`/`-shm` files,
   tokens and permissions together; do not copy just a live main database file.
   Back up adapter-owned session storage separately if exact resume is needed.
3. Start the new executable against the original directory. It upgrades versions
   1/2 through migrations 003/004 without rewriting task IDs or existing bodies.
   Check `doctor`, existing tasks, and a private publish/get cycle.
4. To roll back, stop the new daemon and preserve a separate copy of its complete
   state. Restore the **pre-upgrade** backup to another private directory and run
   the previous executable there. v0.2 rejects schemas 3/4; do not decrement
   `schema_version` or delete collaboration tables in place. New post-upgrade
   work will not be present in the old backup; reconcile it before resubmission.

Each migration is atomic; a later migration failure leaves earlier committed
versions intact. Never delete a daemon lock/WAL to force concurrent ownership.
Do not edit immutable artifact rows to repair corruption. Restore a verified
backup or publish a new context and explicitly bind safe queued work.

## Named-agent example

Create real workspace directories and register/start identities with the existing
`agent create/start` commands. The following uses a human admin token; agent MCP
calls derive their own identity. Match `--addr`/`--data-dir` on all CLI calls.

```sh
meshra collaboration conversation.create '{"title":"API contract","participants":["claude:apmobileprod","codex:implementer","omp:reviewer"]}' --json
# Record conversationId as CONV. Publish as prod using its agent credential:
meshra collaboration context.publish '{"title":"API contract","type":"contract","scope":"payment","content":"Preserve the existing API.","idempotencyKey":"contract-v1"}' --json
# Record contextId as CTX and version 1. Owner/admin explicitly grants readers:
meshra collaboration context.grant '{"contextId":"CTX","agentId":"codex:implementer"}' --json
meshra collaboration context.grant '{"contextId":"CTX","agentId":"omp:reviewer"}' --json
meshra collaboration context.attach '{"conversationId":"CONV","contextId":"CTX","version":1}' --json
meshra collaboration task.delegate '{"conversationId":"CONV","from":"claude:apmobileprod","to":"codex:implementer","instruction":"Review the compatible implementation using the pinned contract.","contextRefs":[{"contextId":"CTX","version":1}],"idempotencyKey":"implement-v1","timeoutSeconds":300}' --json
meshra task status TASK --json
meshra task events TASK --follow --json
meshra collaboration task.delegate '{"conversationId":"CONV","from":"claude:apmobileprod","to":"omp:reviewer","instruction":"Review using the pinned contract.","dependsOn":["TASK"],"contextRefs":[{"contextId":"CTX","version":1}]}' --json
meshra collaboration conversation.events '{"id":"CONV"}' --json
meshra collaboration context.audit '{"contextId":"CTX"}' --json
meshra collaboration context.get '{"contextId":"CTX","version":1}' --json
meshra collaboration context.publish '{"contextId":"CTX","version":2,"content":"New contract; old tasks remain pinned."}' --json
meshra collaboration context.revoke '{"contextId":"CTX","agentId":"codex:implementer"}' --json
```

Replace uppercase placeholders with returned IDs. `from` is an admin-only routing
convenience and cannot impersonate a different agent when using an agent token.
Agent tokens must never appear in command arguments or shared context. Task result
refs are separately permissioned; the result owner/admin must grant a reviewer
before including an implementation result ref in the review task.

MCP example: call `meshra_collaboration_context_get` with
`{"contextId":"CTX","version":1}`, or `resources/read` with
`{"uri":"meshra://contexts/CTX/versions/1"}`. Both require the same reader grant.

## Diagnose safely

- `context_denied`: inspect owner ACL and exact recipient ID; membership is not a
  grant. Revocation fails queued delivery instead of leaking content.
- `dependency_failed`: inspect the prerequisite, then explicitly retry safe work.
  A queued task with `schedulingState=blocked` is waiting for successful dependencies.
- `result_storage_failed`: execution may already have happened. Inspect inline
  result and native session before retrying; reduce result size for new work.
- `artifact integrity failure`: stop affected work and restore a known-good backup.
- Native session already owned: stop the other owned process or use different
  agent names. Do not run parallel native tests with the same canonical IDs.
- Uncertain turn: use existing trace/events, inspect external changes, and only
  manually retry after reconciliation. Cancellation is never a rollback promise.

Contexts, artifacts and their access logs currently have no automatic retention
or garbage collection. Bound disk growth operationally. Task history uses existing
retention; referenced dependencies are retained until their dependents are pruned.
No web UI, automatic planner, role ACLs, binary artifact streaming or write approval
console is provided. See V0.3_TEST_REPORT.md for tested limits and native evidence.
