# Developer Console v0.4

Meshra now serves a chat-first console from the existing local Go daemon. There
is no separate production Node process, cloud service, terminal endpoint, or
second database. SQLite tasks remain the durable message/response source.

## Start and connect

```sh
# Rebuild the embedded frontend when changing its source:
npm ci --prefix web
npm run build --prefix web
go build -o meshra ./cmd/meshra
./meshra serve
```

Open **http://127.0.0.1:7331/console/** (also printed at startup). Paste the local
administrator token into the password field. Its file is `admin.token` in the
configured `--data-dir`, normally `$XDG_CONFIG_HOME/meshra` or `~/.config/meshra`.
The console exchanges that token once for an HttpOnly, SameSite=Strict session;
it never stores the bearer token in browser storage. Sessions expire after eight
hours and are invalidated by a daemon restart or explicit disconnect.

For isolated development use matching `--data-dir` and `--addr` options. Do not
send your administrator token to someone else or put it in a URL. The console is
a trusted **local administrator** surface, not an agent-scoped or multi-user SaaS
login. Agent-to-agent policy/session checks remain independent.

## Real chat demo

1. Open **Agents → Register agent**. Choose an installed harness, a unique name
   (`omp:reviewer`, `codex:implementer`, `opencode:architect`, for example), and
   an existing workspace directory. Registration does not start a model turn.
   Start each desired instance. Provider authentication still belongs to its native
   harness; the UI reports actual startup errors. Claude native verification was
   waived by the operator for this implementation.
2. Open **Chat → New conversation** (Ctrl/Cmd+Shift+O). Select one or more exact
   IDs; workspace, harness, availability and delegation policy are visible in the
   picker. Same-harness instances are separate rows, never aliases.
3. Pick the exact recipient in **To**. Multi-participant conversations initially
   select nobody; no broadcast is implicit. Write a message and send with Enter
   (Shift+Enter for newline), or choose Ctrl/Cmd+Enter in Settings. IME composition
   never submits a message. Multiple selected recipients are admitted separately;
   partial failures are shown by recipient and successful tasks remain visible.
4. Follow real queued/running/completed/error states. Busy/offline agents queue
   through the existing durable scheduler. This relay buffers text until successful
   completion and credential redaction; there is no invented token animation.
   The SSE connection replays sequenced task events and invalidates snapshots.
   Reload restores durable messages plus the locally scoped draft/recipients.
5. Open **Contexts → Publish context**. Supply focused UTF-8 text/Markdown and
   explicitly select authorized readers. The maximum artifact is 64 KiB (or the
   lower server-configured limit); injection defaults to 32 KiB including its
   provenance envelope. Recognized secrets/private keys are rejected. The scanner
   is not an exhaustive detector: never publish credentials or `.env` contents.
6. Return to Chat, choose **Attach context**, select an exact version, and attach.
   Recipient ACL checks run in the UI preflight and again on server admission and
   dispatch. Context ownership and versions are visible. Channel membership never
   grants context access. Old tasks retain pinned versions.
7. Choose **Inspect execution** to see correlation, origin, destination/native
   session, attempts, deadline, dependencies, pinned refs, result artifact and
   paginated execution events. Nested delegation links open the owning parent task.
   Task deep links use `/console/#tasks/TASK_ID`; conversations use
   `/console/#chat/CONVERSATION_ID`.
8. If a task was cancelled/failed/timed out, inspect the trace and external effects
   first. **Inspect & retry** requires explicit confirmation, enforced by a distinct
   console request header. Unknown outcomes remain visibly uncertain. Retry never
   means rollback. An `approval_required` event means the native action was denied;
   these adapters have no interactive approval channel, so there is no Allow button.

Navigation also provides searchable Agents, Tasks and Contexts, Activity/provenance,
and Settings. Start/stop/restart and registration are real backend controls. Agent
identity/workspace editing and arbitrary terminal execution are intentionally not
exposed because their safe contracts do not exist in the audited backend. Outbound
policies can be set when registering agents through the established CLI.

## Interaction and resource behavior

Default theme follows the system; Dark and Light are complete, persisted options.
Ctrl/Cmd+K opens quick search. Dialogs trap focus and close with Escape. Sidebar
resize supports pointer drag and arrow keys; navigation can collapse. Mobile shows
one chat panel at a time with an explicit back button and safe-area-aware composer.
Reduced motion removes transitions. Code is escaped, lazy-highlighted, copyable;
raw HTML and external Markdown images are not rendered.

Timeline pages contain 40 executions; at most eight pages (320 task groups) are
retained in a mounted timeline. Older history is navigable with bounded cursor
pages and a back-to-latest control. Long Markdown initially collapses at 14,000
characters. Trace pages contain at most 256 events. Inbox/search returns at most
100 recent matches. Inbox/agent polling is 30/20 seconds with background polling
disabled; a single active chat SSE feed uses 700 ms bounded SQLite checks and
500 ms UI invalidation coalescing. Native typing/token streaming is not claimed.

Pins, appearance, draft text, selected recipients, attachment refs, read markers,
scroll positions and event cursors are local browser preferences, scoped by origin
and immutable conversation ID. Drafts can contain private text; disconnect does
not delete them automatically. Browser storage failures fall back to in-memory
interaction. Messages and task outcomes are never reconstructed from drafts.
Pending-send keys survive reload so an uncertain admission can be retried without
inventing a new message ID. Editing a draft/recipient/reference creates a new send.

## Development and verification

```sh
# With a local relay on 7331, an optional frontend-only development server:
npm run dev --prefix web
# Production frontend / Go verification:
npm run build --prefix web
npm test --prefix web
go test -race ./...
go vet ./...
# Browser tests against the real Go/SQLite backend with isolated fixture adapters:
npx --prefix web playwright install --with-deps chromium
npm run test:e2e --prefix web
```

The development proxy is loopback-only and rewrites its same-origin API requests
to the local daemon. It is never the production deployment. `web/components.json`
documents the locally owned shadcn/ui Radix primitives and token stylesheet;
`web/THIRD_PARTY_NOTICES.md` records attribution. `package-lock.json` pins packages.
There are no runtime CDN scripts, web fonts or analytics. Checked-in
`internal/consoleui/dist` is embedded by Go; use `npm ci` + build before Go packaging.

Native browser verification requires an isolated real daemon, native credentials,
and explicit opt-in (provider costs apply):

```sh
# Run an isolated daemon separately; use its actual private state directory.
MESHRA_UI_NATIVE=1 \
MESHRA_UI_URL=http://127.0.0.1:37732/console/ \
MESHRA_UI_TEST_DIR=/absolute/path/to/that/daemon-state \
npm run test:e2e --prefix web -- tests/native.spec.ts
```

That test registers/starts real OMP/Codex/OpenCode instances through the UI,
publishes/grants context, creates chat, verifies three actual provider answers,
reloads/replays, and inspects task provenance. It does not pretend that deterministic
fixture adapters are providers. See [V0.4_TEST_REPORT.md](V0.4_TEST_REPORT.md).

## Upgrade, backup and rollback

Schema **5** adds conversation/parent task indexes only. Existing v0.1–v0.3 routes,
MCP tools, task states, IDs, queues and credentials remain supported. Human-origin
tasks use `human:operator` with `console` origin session; no fake harness is
registered. Native reply results still belong to the recorded destination/session.

Stop admissions, reconcile active work, stop the daemon, and back up the complete
private state directory (main DB, WAL/SHM if present, tokens and permissions).
Back up native adapter session storage separately. Start the new executable; its
migration is transactional. For rollback, stop v0.4, preserve its post-upgrade
state for reconciliation, and restore the **pre-upgrade** backup with the previous
executable. Do not manually decrement the schema version or replay uncertain
post-upgrade tasks. Restart invalidates console cookies, not durable messages.

## Local security and remote access

The server still refuses non-loopback listeners. Console requests require a
loopback Host, exact Origin when present, and same-origin Fetch Metadata. Every
mutation requires CSRF except login, which requires a non-simple custom header
and an admin bearer exchange. Legacy `/v1` and `/mcp` continue rejecting browser
Origin headers. Cookies are HttpOnly/SameSite=Strict; HTTPS additionally sets
Secure. CSP blocks remote scripts/frames and MIME sniffing. Administrator tokens
are not returned by any console route.

For remote use, keep Meshra bound to localhost and use an authenticated SSH local
forward, then open that local address. A public reverse proxy, shared browser
account, or multi-user authorization boundary is not implemented or claimed.
Forwarded Host/Origin headers are not trusted to bypass the local boundary.

Current limits: no agent identity editing, file/binary uploads, arbitrary terminal,
automatic write approval, pause/resume, live native typing, or full chat-history
synchronization. Context version publication/grants are exposed; revocation and
new versions remain available through established API/MCP/CLI operations. Context
and audit storage still require operational retention management as in v0.3.
