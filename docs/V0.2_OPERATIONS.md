# Meshra v0.2 operations

## Start and stop

```sh
go build -o meshra ./cmd/meshra
./meshra serve --retention 720h --max-delivery-attempts 16 --retry-base 1s --retry-cap 30s
# In another terminal, with matching --data-dir / --addr if customized:
./meshra doctor --json
./meshra agent list --json
./meshra metrics --json
```

The foreground daemon stops on Ctrl-C/SIGINT or SIGTERM. No broker, cron worker, automatic harness startup, or separate metrics service is required. Default address is `127.0.0.1:7331`; only loopback is accepted, even with a bearer token. Do not expose it using a port forward. Every HTTP/SSE/MCP operation requires authentication; browser Origin requests are rejected.

The private relay directory defaults to `os.UserConfigDir()/meshra` (`$XDG_CONFIG_HOME/meshra` or `~/.config/meshra` on Linux). It contains `meshra.db`, WAL/SHM sidecars, `daemon.lock`, and `admin.token`; directory mode 0700 and token/database mode 0600. A second daemon cannot own the same directory. Do not delete a lock or database sidecar to defeat ownership. Normal CLI commands use this admin token unless `MESHRA_TOKEN` selects an agent token. Never give an administrator token to a harness.

## Registration is not availability

| Persisted state | Operational meaning |
| --- | --- |
| `registered` | Definition exists; no owned runtime started |
| `starting` | Explicit adapter startup in progress |
| `idle` | Owned runtime prepared, no active turn; not proof of provider entitlement |
| `busy` | One turn holds the identity/repository slot |
| `stopped` | Offline after explicit stop or relay restart |
| `error` | Unhealthy startup/interrupted turn; inspect and explicitly restart |

Claude/OpenCode prepare SDK/HTTP runtimes but allocate/start the native query/server per turn; `idle` does not claim an unmanaged terminal attachment. A saved session ID is only resumed through the adapter's verified exact-ID path. Missing native history fails visibly; it never chooses another instance or silently creates a replacement session. Use a deliberately new identity when a fresh session is required. No heartbeat is promised; idle native disconnects may be discovered on the next operation.

```sh
./meshra agent status claude:exampleone --json
./meshra agent start claude:exampleone
./meshra agent stop claude:exampleone
./meshra agent restart claude:exampleone
```

Restarting the relay restores definitions and queued work, not ephemeral handles. Previously active agents become `stopped`; start exact destinations explicitly after inspecting recovery state.

## Inspect, wait, cancel and retry

```sh
./meshra request --from omp:exampleworker --to codex:reviewer \
  --message 'Review the API; return findings only' --idempotency-key review-001 --timeout 90s --json
./meshra task status TASK_ID --json
./meshra task trace TASK_ID --json
./meshra task events TASK_ID --after 0 --follow --json
./meshra task cancel TASK_ID
```

Ordinary send/request returns HTTP 202 and a Task immediately. Add `request --wait --timeout 90s` to wait within an explicit persisted deadline; agents also require status permission. Terminal state returns the same Task (HTTP 200), including failures. A transport deadline can return HTTP 202 with current nonterminal state; keep inspecting. CLI exit 0 means the exchange succeeded, not that `task.state` is completed. Disconnect does not cancel work.

`task trace` contains the current Task, latest 256 retained events, and `eventsTruncated`. Trace data fields are capped at 2048 bytes; use event pages for full retained data. Follow supports persisted sequence cursors and drains terminal history; reconnect using the last fully processed ID. Sequence gaps are normal across tasks and retention. A vanished/expired task returns 404 rather than a fabricated replay.

Native text deltas are buffered in at most 256 KiB per active turn, redacted as complete text, then persisted in bounded chunks before successful completion. Progress/session/approval notifications remain immediate. Failed/cancelled partial text is discarded; native delta count/timing is not a v0.2 API guarantee. This intentional v0.1 timing change closes cross-delta credential leakage. Read the terminal result, not the presence of any delta, as completion evidence.

### Recovery decision

| Observation | Safe action |
| --- | --- |
| `queued`, `destination_offline`, attempts zero | Start the exact destination; no external turn has been invoked |
| `delivery_exhausted`, ambiguity false | Fix availability, start destination, then explicitly retry |
| Busy/repository/global-slot queue | Wait or cancel; no offline retry budget is consumed |
| `failed` with `uncertain_execution` / `adapter_failure`, or ambiguity true | Inspect the exact native session and external effects before any retry |
| Running deadline/cancellation | State is terminal, but downstream cancellation is best-effort; allow the owned invocation to finish stopping |
| 409 previous execution still stopping | Do not create replacement work to bypass the slot; inspect/stop the runtime |
| 429 inbox capacity | Nothing was enqueued; drain/cancel work or resubmit the same idempotency key after capacity is available |

```sh
# Only after a human has reconciled native/external effects:
./meshra agent restart codex:reviewer
./meshra task retry TASK_ID --json
```

Retries retain task/message/correlation IDs and event history, clear current result/error, reset offline checks, and establish a fresh 300-second deadline. At most three dispatch attempts per task; offline checks do not count as native dispatches. Default offline policy allows 16 checks with equal-jitter exponential delays (base 1s, cap 30s); the deadline can expire earlier. Explicit start bypasses an old offline backoff. No potentially invoked task is automatically replayed, even if a lease expired or the daemon died. Cancellation cannot undo tools, MCP effects or remote provider work already performed. This is at-least-once delivery with admission deduplication, not exactly-once execution.

## Permissions and credentials

```sh
./meshra agent create --harness claude --name exampleone --cwd /existing/project \
  --allow-from omp:exampleworker --allow-inbound-operation request
./meshra agent create --harness claude --name exampletwo --cwd /existing/wallet \
  --allow-from=
```

Outbound operations/destinations remain deny-by-default. Recipient lists supplement them: omitted/null lists retain v0.1 inbound behavior; explicit empty lists deny. Administrators retain explicit override authority. Worktree-write enablement is rejected for every current adapter; relaying does not grant approval. Native read-oriented permissions are not universally OS-enforced filesystem containment, particularly with trusted OpenCode native plugins. Use the [enforcement matrix](V0.2_ADAPTER_VERIFICATION.md#enforcement-matrix-worktreewrites-false).

Forbidden sends/requests are recorded in SQLite `audit` and payload-free structured warning logs. Lifecycle JSON logs on stderr include request/message/correlation IDs, sender, recipient, harness/session, state transition, attempt/delivery check, latency, error class, and ambiguity. Do not paste tokens or credentials into prompts/identifiers. Recognized credential patterns and current per-turn tokens are redacted; unknown/unlabelled formats are not guaranteed detectable. Protect native stores and backups; neither SQLite nor harness histories are encrypted by Meshra.

## Metrics and doctor

Metrics describe **retained history**, not unbounded lifetime totals: queued, inFlight, succeeded, failed, expired, messages with retries, offline agents, oldest queue age, and average terminal latency including queue time. Cancellation remains visible in task state but has no separate metrics field. Doctor checks SQLite ownership/connectivity, executable version availability, Claude bridge/pinned SDK manifest, canonical workspaces, and unhealthy registered runtimes. Version drift is reported as unverified/unsupported. Credential validity remains `unknown` without a provider operation; `healthy:true` is not a provider-authentication claim. Successful `doctor` transport exits 0 even if `healthy:false`; automation must inspect the object.

## Upgrade, backup and rollback

1. Stop the v0.1 daemon and owned harnesses. Do not copy only a live main SQLite file while omitting its WAL.
2. Back up the **whole** private relay directory and relevant native state. For example, after shutdown: `cp -a "$DATA" "$DATA.pre-v0.2"`. Keep the backup private.
3. Build v0.2, start against the original directory, run doctor, inspect known task IDs/event cursors, and start only intended identities.

The database upgrades from schema 1 to 2 automatically. API/domain `schemaVersion` remains 1. The transactional migration rebuilds task uniqueness as sender/session/**operation**/key, preserving task sequence, message/correlation IDs, event IDs and foreign-key relationships. It adds relational inbox indexing, event metadata and audit storage, and redacts recognized credentials in legacy task text/results/errors and event data. Invalid legacy JSON/foreign keys abort the upgrade instead of discarding records. Databases newer than schema 2 are refused.

Do **not** run an older binary against an upgraded file. Rollback means stopping v0.2 and using the untouched pre-upgrade directory with the v0.1 binary (or restoring the entire backup to a separate private directory). Preserve the upgraded state for diagnosis rather than deleting it. Restore matching native state when required, and reconcile all effects created since the backup: database rollback is not execution rollback.

OMP/Codex native state is **outside custom relay data directories**, under `os.UserConfigDir()/meshra/runtimes/<harness>/<sha256(agent-ID)>/`. Each identity has a native-state flock across all relay data directories. Codex also depends on native authentication. Claude/OpenCode use their native same-user session/config/auth locations; retain those through native supported backup procedures. Moving only `meshra.db` does not migrate native sessions or credentials. Details: [stdio adapters](adapters-stdio.md), [SDK/HTTP adapters](adapters-sdk.md).

Retention defaults to terminal history older than 720h; use `--retention 168h` or `--retention=-1s` to disable. Pruning runs at startup/hourly, removes task/events transactionally, preserves active invocations and required ancestors, and expires deduplication along with a task. Audit records follow the same age policy. Deleted rows free reusable database pages but do not promise immediate file shrinkage or cryptographic erasure from WAL/free pages/backups. Protect and separately retire backups; native stores are not pruned by relay retention. No destructive database reset is a recovery procedure.

## WSL2 and repeatable load

Keep state on the Linux filesystem, not a Windows-mounted shared path with different locking/permission behavior. WSL shutdown may kill the daemon without cleanup; restart recovery treats interrupted dispatches as ambiguous. Do not automatically redrive them from a shell startup hook. At most 32 independent turns, one per identity/repository, can be active; provider processes have their own memory/cost footprint and can exceed a small WSL allocation even when relay memory is low. Start only needed harnesses.

```sh
# Real executable, local HTTP/SQLite, 1024 messages across 8 offline destinations:
node scripts/load.mjs
# Optional maximum 4096-message queue across 32 destinations:
MESHRA_LOAD_AGENTS=32 node scripts/load.mjs
# Real OMP/Codex provider turns and exact-session restart; charges can apply:
MESHRA_NATIVE_SMOKE=1 node scripts/smoke.mjs
```

Load uses 512-byte messages, one sequential producer per destination, per-inbox overload rejection and duplicate-at-capacity checks, `/proc` RSS/high-water/CPU samples over five seconds, and asserts zero harness children. It launches a temporary real daemon and removes relay state after shutdown. This measures relay-only workload, not model inference or all 6 GB worth of allowed payloads. Exact observed results and live/simulated boundaries are in [V0.2_TEST_REPORT.md](V0.2_TEST_REPORT.md).
