# Add OpenBot-inspired capabilities to Meshra

## Context
Keep Meshra's current implementation and working behavior, adopt better OpenBot patterns where they fit, and add the selected local-agent and automation capabilities. Preserve the Go relay, SQLite data, React console and existing permission defaults. The end state adds portable profiles, richer context/files/queues, approved confined tools, routines, skills, connections and local voice without replacing current workflows.

## Confirmed direction
- Retain Meshra as the foundation rather than replacing it with OpenBot. Preserve existing user data and supported workflows; new capabilities must not silently weaken current authorization or execution permissions.
- Default to independent implementation of product ideas and architectural patterns. OpenBot's current PolyForm Noncommercial license requires a separate commercial license for commercial use; do not copy its code/assets into Meshra's MIT-licensed source without an appropriate license. Primary source: https://github.com/nightly-labs/openbot/blob/main/LICENSE.
- Selected feature scope: local agents and automation. Include profiles/provider continuity, bounded memory/history retrieval, local-model setup, queue controls, attachments/usage, browser/computer tools, approval controls, routines/flows, local skills/templates, MCP management, messaging connectors and voice. Keep Meshra local and single-user; do not add native desktop/mobile clients, remote-access services, team accounts, hosted marketplace or managed hosting.
- Selected execution policy: existing agents remain read-only by default. Write/command execution requires explicit per-agent enablement, workspace confinement and approvals. If confinement is unavailable, refuse write-capable execution rather than silently falling back.
- Preserve the Go relay, SQLite state, React/TypeScript console, canonical harness identities and existing disposable-session direct chat. Represent new provider-portable coworkers separately instead of renaming or transferring existing canonical agent IDs.
- Provider coverage: retain Codex/Claude/OMP/OpenCode, add direct OpenAI-compatible endpoints, and add generic ACP with installed-CLI presets for Gemini/Cursor/Cline. Additional standalone Grok/Pi/Muse/Inception protocol integrations are not selected; compatible services remain usable through configured endpoints/OpenCode/custom ACP where genuinely supported.

## Research findings affecting the design
- Existing `sendLocked` owns the task/event transaction (`internal/relay/tasks.go:116–330`); a routine cannot wrap it in a second transaction with the single SQLite connection. Factor one transaction-aware admission core, retaining all current authorization, fingerprint, queue and ancestry checks; use it for feature receipts and ordinary sends.
- Existing task `seq` defines transcript order (`tasks.go:31–49`), while `tick` enforces deadlines, dependencies, identity and repository locks. Add separate queue dispatch ranks and pause state rather than rewriting task sequence or treating stop as pause.
- Legacy chat history is intentionally scoped to conversation and recipient and uses disposable native sessions (`internal/relay/chat.go:29–77`, `tasks.go:704–729`). Portable-profile conversations must be separate ordinary collaboration conversations associated with profiles, not a global broadening of legacy chat.
- Current context artifacts are immutable text with a 64 KiB storage cap and ACL/audit rules (`internal/relay/migrations/004.sql`, `contexts.go`). Binary attachments need separate blob storage and ownership links; a digest alone must never authorize access.
- Existing `/mcp` is a Meshra tool server, not a client for external MCP servers. Use the official Go SDK for the new client/OAuth lifecycle; preserve the existing server and its credential model.
- Current OMP has a host-tool bridge in the installed bundle (`/home/yogaagungg/.bun/bin/omp:60598–60605`): `set_host_tools`, `host_tool_call`, `host_tool_result` with top-level `isError`, and `host_tool_cancel.targetId`. Current Codex upstream documents experimental `dynamicTools` and `item/tool/call`; actual installed-version schemas still require implementation-time compatibility verification. Both can invoke an in-process broker without a gateway bearer token.
- Claude/OpenCode already connect to per-turn authenticated Meshra MCP. Extend exact opt-in tool allowlists only, retaining native shell/edit/subagent denials. All four harness transports converge on one trusted active-attempt tool broker, not on model-selected identity fields.
- The console already provides same-origin cookie/CSRF authentication, Radix dialogs, TanStack Query, selected-conversation SSE and hash navigation. Add an Automation destination and extend Agents/Settings; browser/computer views display authenticated worker pixels, not arbitrary iframes or a new Electron shell.
- Local connectors can remain inbound-port-free through Slack Socket Mode, Discord Gateway and Telegram long polling. Persist event receipts before ACK/cursor advancement; connector callers must never become administrators or gain approval authority.
- Playwright 1.64.1 and Chromium revision 1248 were found in the local cache by read-only inspection; no browser execution or confinement was verified. No Chromium executable on PATH does not mean no cached browser.
- Sandbox command workers need real namespace confinement, not cwd validation. Browser/desktop egress must cross a policy proxy from a private network namespace. Computer use must operate a private Xvfb display, never host X11/Wayland/WSLg or Windows desktop.
- Voice runtime research found MIT whisper.cpp for local STT. Current Piper is GPLv3; Supertonic code is MIT but models are OpenRAIL-M and its repository is archived. Select and verify a permissively licensed local TTS runtime/model explicitly rather than treating all voice engines or weights as MIT.

## Approach
Implement all selected capabilities as one integrated change. Execution order is 1 → 2 → 4 → 5 → 3 → 6 → 7 → 8 → 9 → 10 → 11 → 12: this creates migrations010–013 and confinement before launching new ACP runtimes; endpoint/ACP configuration tables are created with010. Steps7 and9 can be implemented independently after the broker, and connectors/browser/voice can proceed independently after their stated dependencies, with one integration owner for model/task/schema changes. Keep new routes disabled until their complete backing behavior is present. New paths named below are to be created, not claims that they already exist.

### 1. Preserve the core and add one optional application boundary
- Keep `model.Service`, `Runtime.Run(context.Context, Turn, Emit)`, `Factory`, existing canonical IDs, existing task states, and legacy chat behavior. Use `internal/model/automation.go` for the new optional interface `AutomationService { Automation(context.Context, Principal, string, json.RawMessage) (any, error) }`. Implement it on `Relay` in feature-specific files, not a second daemon or replacement scheduler.
- Add POST `/v1/automation/{operation}` behind bearer auth and POST `/console/api/automation/{operation}` behind the existing session/CSRF boundary. Operation names are the literals specified below. Decode each payload into its own request struct with unknown-field rejection; retain `{error:string}`, 400 invalid input, 403 denied, 404 unknown resource, 409 stale/busy/conflict, 413 size bound, 429 capacity, and 503 unavailable dependency. Queries return 200, creates 201, task admission 202. No legacy endpoint changes meaning.
- Add `web/src/automation-api.ts` with typed wrappers over existing `api`; no automatic retries for admission, approval, connection mutations or execution. Dedicated upload/download helpers retain the same cookie/CSRF/401 behavior without JSON-encoding binary bodies.
- Factor `sendLocked` into `admitLocked(p model.Principal, q model.SendRequest, meta *admissionMeta) (model.Task,error)`. Ordinary sends use nil metadata and retain existing checks. At this shared boundary, reject sends to profile-managed identities unless trusted metadata resolves the exact profile/conversation/binding/snapshot; raw REST/MCP, including raw administrator sends, cannot bypass it. Prepare reads before opening the transaction; atomically insert task/events plus feature receipt/snapshot/link rows. Metadata is never HTTP/MCP JSON.
- For routines/connectors, `admissionMeta` contains a verified durable ingress grant, source ID, exact target and conversation; authorize only that grant without creating an admin principal or issuing its credentials to the source. Persist source attribution separately from the human operator. Validate target, scope and enabled revision on every admission. Agent delegation still uses its real principal and the existing ancestry/policy checks.
- Sequentially embed migrations 010–018 in `relay.go` and extend `migrate` in `reliability.go`; keep version rejection before writes, per-migration transactions, FK validation and all old IDs/sequences intact. Database schema version becomes 18, while `model.SchemaVersion` remains 1. Introduce each migration with the behavior that uses it, not unused public endpoints.
- Run LSP references before editing existing exported `Agent`, `Turn`, `Task`, `SendRequest` and `ModelOption`. Earlier read-only reference queries found 95 Agent, 71 Turn and 72 SendRequest sites. Their production consumers are the four adapter packages, relay startup/execution, API/MCP serialization and CLI request construction; update these plus test fixtures where additive fields are needed. Do not add compatibility aliases or broaden old JSON fields into arbitrary configuration.
- Add `Principal.ConsoleSessionID string` tagged `json:"-"`, set only by the console handler from its validated cookie digest; bearer/MCP/routine/connector callers never set it. Console-only operations require Admin plus this provenance and are rejected on `/v1`. Add optional `SetConsoleSessionValidator(func(string) bool)` and `RevokeConsoleSession(string)` integration: the server injects a validator against its real session store and revokes on logout/expiry/revoke/password-change invalidation. Never invoke relay hooks while holding the API session mutex; do not hold the relay mutex across validator callbacks. Revalidate before decisions/worker dispatch; revoke session-owned jobs/leases/OAuth flows/pending decisions. Started effects remain potentially irreversible. Include Principal in the LSP sweep.

### 2. Introduce profiles without migrating canonical identities
- Migration 010 adds `agent_profiles(id PK,revision,body)`, `profile_bindings(id PK,profile_id,conversation_id,generation,agent_id UNIQUE,body,UNIQUE(profile_id,conversation_id,generation))`, `profile_conversations(conversation_id,profile_id,PRIMARY KEY(conversation_id,profile_id))`, `profile_task_snapshots(task_id PK,profile_id,profile_revision,binding_id,body)`, `profile_context_epochs(binding_id PK,epoch,reset_after_seq)` and `automation_events(seq INTEGER PRIMARY KEY AUTOINCREMENT,kind,resource_id,profile_id,data,time)`, plus endpoint/ACP/secret tables from step3. IDs use existing `randomID`; foreign keys/indexes cover profile/conversation/task lookups.
- Profile JSON: `{id,revision,name,instructions,avatarAttachmentId?,workspaceId,binding:{harness,config,connectionId?},capabilities,allowedProfileIds,notificationsEnabled,archived}`. Bound name to128 UTF-8 bytes/instructions16 KiB, use existing credential/text validation, reject unknown workspace/attachment refs. `capabilities` is `{workspaceRead,workspaceWrite,command,browser,computer,memoryWrite,externalMcp,attachments}`; reads/attachments/memory may be enabled explicitly at creation, all execution/external capabilities start false. Routing/tool permissions remain separate. Existing named agents stay unchanged; opting into a profile creates new execution identities rather than silently upgrading them.
- Binding JSON: `{id,profileId,conversationId,generation,agentId,harness,config:{model?,provider?},connectionId?,toolCatalogDigest}`. Resolve a separate native binding for every profile/conversation pair, including connector threads; never reuse a personal-chat native session for external messages. Create backing agents named `profile-<first8 profile-id>-<first8 conversation-id>-<generation>` through the existing registry validation; never rename/adopt registered agents, rewrite old task ownership, reuse tombstones or mutate managed chat. Mark them `profileManaged` so Named agents is not cluttered. Profile creation has no provider turn; first conversation materializes its binding.
- Operations: `profiles.list {after?,limit?}`, `profiles.get {id}`, `profiles.save {id?,expectedRevision?,name,instructions,avatarAttachmentId?,workspaceId,binding,capabilities,allowedProfileIds,notificationsEnabled}`, `profiles.archive {id,expectedRevision,archived}`, `profiles.switch {id,expectedRevision,binding,shareHistory:true}`, `profiles.send {id,conversationId?,text,attachmentIds?,idempotencyKey,timeoutSeconds?}`. Pagination50/max100. Switch/workspace/policy widening requires no nonterminal tasks, pending approvals or reserved unadmitted flow steps referencing the profile/binding; otherwise409. Archive blocks future admission/routines, retains history, and does not silently cancel running work. Retain binding revisions until reservations settle or the run is explicitly canceled.
- Profile chat is an ordinary existing collaboration conversation associated through `profile_conversations`, owned by the operator. Legacy `chat_conversations` and `chatPrompt` remain unchanged. New profile sends resolve one exact binding at admission, persist the revision/config/tool-policy snapshot, and explicitly start that backing agent if stopped. Snapshot failure rolls back admission.
- Add `profiles.createConversation {title,profileIds,kind:"chat"|"task"|"channel"}` (one profile for chat/task,2–64 for channel), `profiles.conversations {after?,limit?}` and `profiles.bindingAction {profileId,conversationId,action:"start"|"stop"|"restart"}`. Materialize each participant's separate binding and return the ordinary conversation plus profile metadata. Add optional `Conversation.ProfileIDs []string`/`profileIds` to Go/TypeScript responses, updating its LSP-discovered consumers; legacy responses omit it. New profile/channel sends select one explicit recipient/owner, never broadcast. Historical bindings cannot restart or accept new work, including through raw Action routes; current bindingAction is the reviewed control.
- Provider switch creates fresh bindings/sessions for that profile's existing conversations, retaining profile/workspace/conversations/memories; it does not merge those conversations. Add the new binding only to each corresponding conversation, retain prior participants as historical bindings, stop old runtimes and revoke live credentials; do not grant unrelated contexts. Old tasks keep original canonical/session ownership. Preview each bounded handoff and provider disclosure before `shareHistory:true`.
- When switching, explicitly regrant only the context versions currently pinned to the affected conversation and authorized for the operator; include them in the provider-sharing preview. Never copy unrelated context ACLs. Historical bindings retain provenance but no new admission/control authority.
- `profiles.send` queues follow-ups and returns a durable task. Add adapter capability `durableHistory`, true only for actually resumable native history. For stateless OpenAI-compatible sessions and ACP without durable load/resume, reconstruct at most32 KiB from the exact conversation on every turn, respecting reset cutoff and excluding current/later queued tasks; preserve assistant/tool-call/tool-result ordering in the active loop. Resumable native sessions receive handoff only when newly started/rotated. Always inject current labeled instructions/eligible memory/skills. Cross-profile requests join only the explicitly authorized shared conversation, never a private chat.
- Add `profiles.generate {description,harness,config?,workspaceId}`: execute a normal metered, tool-free task asking for a structured profile draft. Parse and validate name/instructions only, return an editable draft; never save permissions, install tools or start routines from model output. Invalid structured output is a visible draft error, not guessed settings.

### 3. Add first-class endpoints and generic ACP, not another provider-specific architecture
- In migration 010 add `provider_endpoints(id PK,revision,body)`, `acp_agents(id PK,revision,body)` and `automation_secrets(id PK,kind,nonce,ciphertext,updated_at)`. Secret values are write-only API inputs; summaries expose `missing|saved|unreadable`, never decrypted values.
- Add `internal/relay/secrets.go`: AES-256-GCM with a random 32-byte `automation.key` in the existing 0700 data directory, created exclusively with 0600 permissions and used as associated data with secret ID/kind. Persist ciphertext before reporting success. If the key is missing/unreadable while ciphertext exists, mark dependent connections unavailable and preserve data; never regenerate over encrypted records or fall back to plaintext. This does not protect against the same OS user/root; keep native harness auth stores unchanged.
- Register active vault secret values/common URL-escaped forms with a scoped redactor before error/event/log/tool-text persistence; regexes alone miss arbitrary keys, Slack app tokens, Telegram path tokens and OAuth material. Never log raw auth URLs/codes/headers. Binary files remain byte-exact, and content redaction is not a universal secret detector.
- Endpoint JSON: `{id,revision,name,baseUrl,enabled,secretRef?,supportsTools,supportsImages,contextWindowTokens?}`. Cap URL at 2048 bytes, reject credentials/query/fragment, allow HTTPS or explicitly configured local/LAN HTTP, pin requests to the configured origin and refuse redirects. `connections.scanLocal {}` probes only `http://127.0.0.1:11434/v1/models` and `http://127.0.0.1:1234/v1/models` after a user action, without credentials; five-second/2 MiB bounds, no subnet scan. Discovery is not authentication or a promise of model capabilities.
- Operations `connections.list`, `connections.saveEndpoint {expectedRevision?,endpoint,apiKey?}`, `connections.models {id}`, `connections.disable {id,expectedRevision}`, `connections.remove {id,expectedRevision}`. A used connection cannot be removed; disable blocks new admissions and cancels pending connection probes, not completed history. Active turns retain their immutable admitted configuration; secret revocation stops new calls immediately.
- Add `internal/adapters/openai/`: a real text/image/tool-call loop over `POST <baseUrl>/chat/completions`, model list over GET `<baseUrl>/models`, with normalized `/v1` base URLs, request-context cancellation, bounded responses and no automatic replay of a model/tool request after uncertain failure. Use `net/http`; no new model SDK is necessary. Limit to 40 tool calls and one outstanding broker mutation per turn; tool arguments must parse/validate before invocation. Sum reported input/output/cached usage across calls; unknown values stay unknown. Model images/tools/context capacity are advertised or operator-declared capabilities, shown as such rather than invented.
- Register harness `openai`; its `Config.Provider` names an endpoint ID and `Config.Model` is required. Add harness `acp`; its Provider names an ACP configuration ID and Model may select an advertised option. Update the exact harness checks in `createLocked`, `validAgentID` (`internal/relay/security.go:34`), `validConfig`, adapter registration and new-profile selectors; existing four-harness managed chat remains unchanged.
- Add `internal/adapters/acp/` using existing bounded JSONL/process transport and independently implemented ACP v1 wire structs. No Go ACP client exists in this repository; reuse the existing transport, not another RPC framework. Support initialize/capability negotiation, session/new, advertised load/resume only, session/prompt/update/cancel, advertised model config options, permission requests, client file/terminal requests and optional HTTP MCP or a confined stdio Meshra proxy when HTTP MCP is unsupported. Reject unsupported protocol versions; v2 is draft and not silently treated as v1.
- ACP configuration is `{id,revision,name,preset,executable,args,runtimePaths,secretEnvRefs,readOnlyAuthFiles,allowedOrigins,enabled}`. Executable must resolve to an existing absolute regular executable; args are an array, never shell text. Presets: Gemini `gemini --acp` (official current guide), Cursor select installed `cursor-agent acp` or official `agent acp` through explicit executable selection, Cline `cline --acp` with `CLINE_SESSION_BACKEND_MODE=local` and `CLINE_NO_AUTO_UPDATE=1`. Scan detects paths only; Check performs initialize/new-session in disposable state with no model turn. Do not download proprietary CLIs or change user configuration.
- `connections.saveAcp`, `connections.checkAcp`, `connections.authenticateAcp` and `connections.acpStatus` use the same revision/secret rules. Authenticate only a method advertised by initialize, with user-initiated browser/device-code flow or existing native CLI sign-in; never ask for passwords in chat. Launch ACP inside the confined read-only profile from step 5, isolated HOME/state and only explicitly selected auth files/secret environment. A protocol permission is not an OS boundary. Refuse new ACP execution when confinement is unavailable rather than launch an arbitrary command on the host.

### 4. Add scoped history, durable queue controls, files and truthful usage
- Migration 011 adds `profile_memories(id PK,profile_id,conversation_id,scope,revision,content,source_task_id,pinned,updated_at)`, an FTS5 index of profile-associated task text/final replies with unindexed ownership IDs, `agent_queue_state(agent_id PK,paused,revision)` and `task_dispatch_order(task_id PK,agent_id,rank)`. Delete FTS rows with task pruning; no unlimited duplicate transcript. Memories survive ordinary retention until deletion; max256/profile,4 KiB each,8 KiB injected pinned-first/updated-time order. `scope:"operator"|"conversation"`; default operator-created memory is operator-only, agent-created memory is scoped to its current conversation. External connector/flow conversations never receive operator-only memory without an explicit operator share into that conversation.
- Operations: `history.search {profileId,conversationId,query,after?,limit?}` (literal FTS phrase,max20 results/400-byte excerpts), `history.read {profileId,conversationId,taskId?,before?,offset?,limit?}` (max20 exchanges/16 KiB), `memory.list {profileId,conversationId?}`, `memory.save {profileId,id?,expectedRevision?,content,pinned,scope,conversationId?,sourceTaskId?}`, `memory.remove {profileId,id,expectedRevision}`. Agent calls are forcibly scoped to the trusted current conversation; scope widening/removal of operator memory requires the operator. Check source access every time. Quoted memories/history are data, never policy; do not broaden legacy history queries.
- Profile context rotation retains the same canonical binding/queued task destinations but replaces only its native session between turns. Before the next claim, a reported fill>=80% closes the idle runtime, clears its resumable native session, advances its context epoch and starts fresh with the bounded handoff; wait for teardown before releasing the identity/repository lock. Do not interrupt an active turn, fabricate capacity or invoke paid summaries. Manual `profiles.resetContext {id,conversationId,expectedRevision}` requires no nonterminal work and advances `reset_after_seq` to exclude prior transcript from future handoffs/history tools while retaining explicitly saved memory. Old task/session fields never change. Missing context stays unknown; failed fresh startup leaves queued tasks visible and the agent in error, not silently rerouted.
- Operations: `queue.list {agentId?,profileId?}`, `queue.pause {agentId,expectedRevision}`, `queue.resume {agentId,expectedRevision}`, `queue.reorder {agentId,expectedRevision,taskIds}`. Reorder must name the exact current set of queued tasks for that recipient; otherwise 409. Paused queues still expire/cancel but do not claim work or consume offline delivery checks. Rank affects dispatch only within a recipient; dependencies, repository serialization and global limits still win. Keep immutable `tasks.seq` for timeline/regeneration. Legacy single-active chat admission remains unchanged.
- Migration 012 adds `attachments(id PK,sha256,size,mime,name,owner,created_at,body)`, `attachment_conversations(attachment_id,conversation_id)`, `attachment_tasks(attachment_id,task_id,role)` and attachment read audit. Store bytes under `<dataDir>/attachments/<random-id>` using exclusive temporary files, digest verification, 0600 permissions and atomic publish; never serve by filesystem path or digest alone.
- Add POST `/console/api/attachments/upload?conversationId=...` as a bounded single-file binary upload with CSRF and safe filename metadata; GET `/console/api/attachments/{id}` with membership/authentication, `nosniff` and attachment disposition for active content. Max25 MiB/file, four files/message, default total store quota1 GiB; reject before admission when unavailable/over capacity. User-selected text/image/PDF/ZIP/binary attachments remain byte-exact; never run or auto-extract uploads or render uploaded HTML as console-origin HTML.
- Upload may omit conversationId for an operator-private draft (needed before profile/conversation creation); only the operator can read it until bound. Avatars accept validated PNG/JPEG/WebP<=512 KiB, never SVG/HTML. Add `attachments.list {conversationId?,after?,limit?}` and console-only `attachments.remove {id,confirm:true}`; removal makes references visibly unavailable without erasing transcript/audit provenance. Expire unattached drafts24h; keep referenced files until explicit deletion or final-owner retention pruning.
- Add `attachmentIds` to SendRequest and Task as an optional field; include normalized immutable refs and relevant profile snapshot in the fingerprint only when present, keeping old fingerprints byte-for-byte compatible. Validate access at admission and tool read/dispatch. Text attachments are bounded/redacted excerpts; binary/image attachments are addressed through scoped tools, not silently converted to filenames. Add image tool-result encoding to OMP/Codex/Claude/OpenCode/ACP/openai only where the selected model declares support; otherwise admission reports the unsupported format instead of pretending the model read it. A file-read tool can stream bounded chunks for binary analysis; it does not grant filesystem execution.
- Add `attachments.read`/`attachments.attachResult` broker operations with exact task/conversation ownership. Agent file publication copies an approved sandbox file to immutable storage; grant recipients explicitly. Reuse text Contexts for small textual results and retain its immutability/ACL rules unchanged.
- Extend run usage rows with nullable `profile_id`, `profile_revision`, `binding_id`, actual reported model/provider and optional `reported_cost`/currency only when natively reported. Preserve current byte/turn/token accounting and Codex/OMP quota limits; do not invent costs or subscription quotas. Surface source, partial coverage and stale state after provider changes.

### 5. Build the approval broker and real confined execution boundary
- Migration013 adds `profile_tool_policies(profile_id PK,revision,body)`, `automation_runtime_settings(id PK CHECK(id=1),revision,body)`, `network_grants(id PK,revision,profile_id,connection_id,origin,enabled,body)`, `tool_invocations(id PK,task_id,attempt,call_id,action_hash,state,body,UNIQUE(task_id,attempt,call_id))`, `tool_approvals(id PK,invocation_id UNIQUE,revision,status,expires_at,body)`, `workspace_changesets(id PK,invocation_id,manifest_hash,state,body)` and the per-file apply journal.
